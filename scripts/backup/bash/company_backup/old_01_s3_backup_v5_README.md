# 스크립트 실행 흐름 요약

이 스크립트는 **"준비 → 작업 실행 → 마무리"**의 명확한 3단계 구조를 가집니다. 각 백업 작업은 독립적으로 실행되어 하나의 실패가 다른 작업에 영향을 주지 않도록 설계되었습니다.

---

## 1단계: 시작 및 준비 (`main` 함수 시작 부분)

### 중복 실행 방지 (`flock`)

- 스크립트가 시작되면 가장 먼저 `/var/run/01_s3_backup.lock` 파일을 이용해 잠금을 시도합니다.
- 만약 다른 스크립트 인스턴스가 이미 실행 중이라 잠금을 얻지 못하면, "스크립트가 이미 실행 중입니다"라는 로그(종료 코드 7)를 남기고 즉시 종료됩니다.

### 정리 작업 예약 (`trap`)

- 스크립트가 어떤 이유로든(정상 종료, 오류, 강제 종료 등) 종료될 때 항상 `cleanup` 함수가 실행되도록 예약합니다. 이는 스크립트가 비정상적으로 끝나도 뒷정리가 보장되도록 하는 안전장치입니다.

### 사전 시스템 점검 (`pre_run_checks`)

- **S3 연결 확인**: `aws s3 ls` 명령으로 S3 버킷에 정상적으로 접근할 수 있는지 확인합니다. 실패 시 스크립트를 종료합니다 (코드 8).
- **디스크 용량 확인**: 시스템의 모든 디스크 파티션 사용량을 확인합니다. 하나라도 90%를 초과하면 디스크 부족 위험으로 간주하고 스크립트를 종료합니다 (코드 1).

---

## 2단계: 개별 백업 작업 실행 (`main` 함수의 `for` 루프)

`BACKUP_JOBS` 배열에 정의된 각 백업 작업을 순서대로 하나씩 실행합니다.

### 작업 격리 (서브셸)

- 각 백업 작업(예: `AC`, `AO_DB` 등)은 `( ... )` 괄호로 감싸인 **독립된 환경(서브셸)**에서 실행됩니다.
- **핵심**: 이 구조 덕분에 한 작업(예: `AO_LOG`)이 실패하여 `exit` 하더라도, 해당 서브셸만 종료될 뿐 스크립트 전체는 중단되지 않습니다. 메인 스크립트는 다음 작업(예: `DK_DB`)을 계속 진행합니다.

### 변경 사항 감지 (`generate_diff_list`)

- 각 작업의 백업 경로(`backup_path`)에 있는 현재 파일 목록(`_current.txt`)을 생성합니다.
- 이전 백업 시점의 파일 목록(`_previous.txt`)과 비교하여, 새로 추가되거나 변경된 파일만 찾아 목록(`_diff.txt`)을 만듭니다.
- **결과**:
  - **변경 있음**: 다음 단계로 진행합니다.
  - **변경 없음**: "백업할 새로운 파일이 없습니다" 로그(코드 3)를 남기고 해당 작업은 여기서 종료됩니다.

### 백업 모드에 따른 처리

- **`sync` 모드일 경우 (`handle_sync_mode`)**:
  1.  `aws s3 sync` 명령어로 변경된 파일들을 S3에 직접 동기화합니다.
  2.  업로드 후, 변경 목록에 있던 각 파일에 대해 로컬 파일 크기와 S3 객체 크기를 비교하여 업로드가 잘 되었는지 검증합니다.
- **`comp` 모드일 경우 (`handle_comp_mode` → `process_archive_group`)**:
  1.  변경 목록의 파일들을 디렉토리와 월(`YYYY-MM`)을 기준으로 그룹화합니다.
  2.  각 그룹별로 다음 과정을 수행합니다.
      - a. **압축 (`create_or_update_archive`)**: 그룹에 속한 파일들을 `.tar.zst` 파일로 압축합니다. 만약 같은 월의 압축 파일이 이미 있다면, 새로운 파일을 추가하는 방식(`tar --update`)으로 업데이트합니다.
      - b. **S3 업로드 및 검증 (`upload_and_verify_s3`)**: 생성된 압축 파일을 S3에 업로드하고, 로컬 파일과 S3 객체의 크기를 비교하여 검증합니다.
      - c. **원본 삭제 (`delete_original_files`)**: **(중요)** 압축과 S3 업로드/검증이 모두 성공했을 때만 백업된 원본 파일들을 삭제합니다. 어느 한 단계라도 실패하면 원본은 절대 삭제되지 않습니다.

### 실패 처리

- `comp` 모드에서 압축이나 S3 업로드에 실패하면, 실패한 압축 파일의 경로가 임시 로그 파일(`FAILED_ARCHIVES_LOG_FILE`)에 기록됩니다.
- 작업이 실패하면, 다음 실행 시 해당 파일들이 다시 백업 대상이 되도록 `_previous.txt` 파일은 업데이트되지 않습니다.

---

## 3단계: 마무리 (`cleanup` 함수 실행)

모든 작업이 끝나고 스크립트가 종료될 때, `trap`에 의해 예약된 `cleanup` 함수가 실행됩니다.

### 임시 파일 정리

- 작업 중에 생성된 모든 임시 목록 파일들(`_current.txt`, `_diff.txt` 등)을 삭제합니다.

### 실패한 결과물 정리

- 스크립트가 오류로 종료되었을 경우에만, `FAILED_ARCHIVES_LOG_FILE`에 기록된 경로를 찾아가 실패한 작업으로 인해 생성된 불완전한 압축 파일만 정확히 골라서 삭제합니다. 성공적으로 완료된 다른 작업의 결과물은 건드리지 않습니다.

### 최종 정리

- `cleanup` 로직에 사용된 임시 파일들을 모두 삭제하고, "스크립트 종료" 로그를 남기며 모든 과정을 마칩니다.
